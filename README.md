# 抖店折扣守护

Windows x64 桌面软件：登录抖店后自动识别店铺和当前单品直降活动，显示商品与逐规格价格。开启守护后，程序在专用无头浏览器中巡检，按已记录的原折扣恢复，并独立回读确认。

浅色界面提供折扣概览、价格确认、店铺管理、运行记录和 GitHub 软件更新。关闭窗口会隐藏到托盘，后台继续运行。

安装新版后，桌面会独立显示后台切换阶段、已安装版本与实际后台版本。先暂停旧后台的新任务并等待当前工作收尾；两分钟没有实质进展或后台工作等待达到五分钟时，检查安全接管条件。仅在同一后台确认停止写入、完整数据库没有未完成或未知任务、进程归属明确且备份核验通过时关闭旧专用进程。否则明确显示未完成原因和重试入口，保留任务及数据库。新版启动后还须核对真实版本、构建与原守护运行状态，不能仅凭安装完成就显示更新成功。

安装包不包含店铺账号、登录资料、商品历史或价格授权。不同店铺独立保存资料；换电脑后重新登录即可读取当前折扣。原机器已有但平台已删除的历史折扣，不会凭空出现在新电脑上。

当前工程版本见 `package.json`，已安装版本见“软件更新”；发行包内源码与说明保留该版本的快照。日常巡检优先读取进行中和未开始的活动，历史单独补读；每个活动核对完成后立即更新界面。数据不完整或过期时不把证据不足显示成“0 个生效折扣”。旧异常保留重试间隔，新发现的失效优先处理，提交前仍独立复查。

beta.46 识别平台回收站新空状态文案“当前分类下未找到符合条件的商品”，继续核对查询条件、表格结构、零条记录和两次稳定读取。活动选品查不到、回收站也为空时，独立查询商品管理的“全部”分类；核验店铺后，在本次读取期限内等待页面稳定，再核对商品 ID、唯一结果及状态列，确认一致后显示“商品已下架”并跳过恢复。空结果本身不认定下架或删除。商品状态核对失败时，在关闭页面前保存商品编号、查询值、表头、数量和实际行，供后续诊断。原折扣自动重建仍按店铺开启一次，保留原价、时长、活动规则及全部价格确认保护。

支持限量抢购的识别、守护及已授权店铺迁移。数量按商品总量保存，多规格共用；分别核对各规格折扣、活动时长和续期。未开启“原折扣自动重新建立”时，仅在对应商品存在明确风险退出证据时恢复。开启后，到期或原活动查不到时可按本店授权的已保存价格、时长和额度重新核验创建；售罄、明确下架、回收和作废继续保留保护。升级不会自动作废其他店铺活动或复制本店的价格授权。

新识别的限量、限时活动分别保存精确到秒的原始时长，不同时长分组恢复。恢复起止时间顺延，保留如“28天加7秒”的时长；已明确确认的活动切换方案优先采用其确认时长。只读日期框通过平台日历与时、分、秒控件操作，草稿及提交后独立回读都核对完整起止时间。平台拒绝原时长或控件无法核实则保留受阻，不取整、不强行成功。beta.26 中因日期错误而阻断、提交次数为0的任务，在正常15分钟重试冷却到期后通过巡检重新核验；未知提交仍只回读，不重试。旧版没有记录时长的限时历史保留旧恢复规则，直到读取到可核对的新记录；不会凭日志猜测原时长。

几百件商品按规则、折扣分组，每批最多 50 件、500 个规格；超出规格预算的单件独立处理。批量选品和预查共用页面，第一批准备好即执行，不等待所有商品预查完毕。活动较多时，恢复前最多并行 6 个只读查询，核对本批确切商品，共用同一原活动的当前详情及退出明细，不重读全部无关活动。少量活动可共用完整当前活动核对；读取超时会改用本批商品查询。证据保留真实时间，过期仍需重新核对，未知提交不重试。批量大小会受实际折扣分组、规格数和平台加载速度影响。

平台把风险商品从活动详情移除时，程序可通过该活动页面的官方下载入口核对逐商品退出原因。无法验证的渠道、下载失败、自然结束或售罄都不会获得恢复许可。明确违反 SKU 价差规则的商品单独显示等待处理，其他合格商品继续；不会按已被拒绝的价格反复创建。迁移交接分别记录原来创建成功、当前仍有效和后来被剔除，保留原回执，不把历史成功当作当前状态。

当前活动详情短暂读取超时会关闭失败页面，换页重新核对店铺并最多重读一次；再次失败仍不判断折扣缺失。历史补读保持原有次数限制，提交不会因此重试。刷新中保留明确注明时间的“上次读取”价格，仅用于查看；上次成功巡检时间跨重启保留。

商品目录每页显示 16 件，规格按需展开。自动刷新保留同店同商品的键盘焦点，不抢搜索框焦点或主动滚动；搜索和翻页复用目录版本标识，避免反复处理全店规格。

活动详情分批读取及历史预查之间会检查当前活动变化。已知活动消失或完整详情中的商品被移除时，先进行商品专属查询和原价、规格核对；符合条件的原折扣恢复无需等待其余详情全部读完。监测线索跨重启保留且按店铺隔离，不包含价格或执行授权。

活动列表监测可与最多六个只读详情查询并行，减少相互等待。每批详情读取和已启动的监测全部收尾后才进入恢复操作；暂停或读取中断也会等待监测收尾，避免与下一家店铺或更新交接重叠。

依赖平台页面可用性、登录状态、完整扫描与独立回读，不承诺秒恢复。完整草稿中可核实的逐 SKU 数值上下限会形成价格建议，选择最接近已有守护价的合法 0.1 折档位，展示原价、现有折扣、建议折扣及增减金额。默认由本人明确确认后才执行该确切目标。无法核实的提示继续保留受阻，不猜测或试填价格。

平台退出明细明确给出 SKU 最高价与最低价的倍率限制时，可生成整件商品的逐规格建议；倍率推算不属于“平台明确数值下限自动提价”，仍需本人确认全部确切价格。价格确认按完整记录计数，每页显示 10 份，待确认优先，历史可继续翻页，不截断大店超过 200 条的记录。过期建议需重新核对。

“店铺管理”可单独授权本店自动提价，默认关闭。仅限平台明确要求提高折后价，且本商品所有规格均无需降价的情况；先记录对应授权与确切目标，再重新核对失效、规格和草稿后提交、独立回读。自动规则与人工逐 SKU 确认分开记录。任何进一步降价都仍需本人确认，包括从已提高的守护价降回较早的原价。停止自动提价只停止生成新目标，此前按授权确定的确切价格继续守护。

换电脑时，可在店铺管理暂停守护并保存专用迁移备份。新电脑登录同一店铺、核对历史价格并确认导入后，保留完整历史、排除项和任务审计；未知提交只回读，不重复创建。备份不含登录资料、可执行的调价批准或自动提价授权，也不会自动开启新电脑守护。诊断文件不能用作迁移备份。


### beta.38
跨期活动按确切退出商品追踪；开启续期且已核对自然到期的限量活动继续按原规则守护。价格限制和无法证明的退出分别进入逐SKU价格确认或明确的重新创建确认。确认/重核请求以SQLite事务原子持久化，按50商品/500规格优先执行，保留未知提交保护。专用会话资料使用当前Windows用户DPAPI加密，登录失效在整个界面提示；重新登录复用该店原目录。


## beta.41：更新目录短暂占用恢复

Windows 临时占用已复制的新版本目录时，程序在有限时间内重试同一目录的切换，保持原后台、数据库和登录资料。并发准备得到相同且完整的目录时直接复用；目标不完整、内容变化或长期占用会显示具体原因并停止，不覆盖目录，不把安装成功当成后台已升级。包含 beta.40 的原折扣自动重建与恢复失败原因展示。

## beta.40：原折扣自动重建、恢复原因展示与规格预查超时

店铺管理增加“原折扣自动重新建立”：每家店确认一次，保持已保存或已确认的规格价格、活动类型、时长及限量额度，允许原活动缺失或到期后的正常重新核验与创建。该设置默认关闭，不会代替新价格或活动类型的本人确认；明确售罄、下架、回收、作废和未知提交仍按保护规则处理。其他电脑升级后，在自己的店铺开启此设置即可免去逐件重建确认；授权保存在该电脑，不随分享包传递。

价格确认页同时展示“其他待核验的恢复”，未形成价格方案的商品也显示最近失败原因与核对时间。显示快照不参与执行或批准。

单商品和批量规格预查纳入有时限的页面读取与清理。超时结果不能回填，清理未确认时暂停写入。安全更新接管同时识别这两个未提交的预查阶段，仍需完整数据库检查、备份、停止确认和确切进程身份。

隔离测试与实店验收分别记录；不能用本地批量场景或一次恢复承诺全店即时恢复。

## beta.39：限时活动退出原因与价格确认

限时抢购失效后，程序重新核对最近一次已回读活动的确切编号、当前详情及原生退出表。3.5倍、5.3倍等已读倍率交给逐规格价格确认；即使旧商品行仍保留，也不继续按已拒绝价格创建。退出表缺失、过期、错店铺、错活动或重复商品时暂停该商品并显示原因，其他合格商品继续。

现有有效活动优先，旧活动的限制不会覆盖新活动。新算法价格仍须本人确认；只提高低价规格无解时显示原因。保留现有价格批准、完整历史、未知提交只回读和限量售罄保护。测试夹具与真实店铺验收分别记录，不取消有效活动制造测试。
